# 매물관리 필터 레이아웃 프로토타입

운영 화면을 수정하기 전에 필터의 정보 구조와 상호작용 모델을 비교하기 위한 독립 데모다.

## 실행

```bash
cd prototypes/property-filter-layouts
npm run dev -- --port 4174
```

브라우저에서 `http://127.0.0.1:4174/`를 연다. 하단 picker 또는 숫자키 `1`–`3`, `←`/`→`로 안을 전환한다. 선택한 안은 `?v=` URL 파라미터에 유지된다.

Electron 창에서 확인하려면 dev server 실행 후 다른 터미널에서 다음을 실행한다.

```bash
npm run electron:preview
```

## 공통 설계 전제

- 사용자: 통화와 상담 사이에 매물을 반복 검색하는 부동산 중개사
- 핵심 과업: 거래유형과 주소를 먼저 좁히고, 영업 상태·금액·면적·입주·광고 조건으로 결과를 빠르게 확정
- 시각 방향: 등기 서류 같은 따뜻한 흰색, 흑연색 텍스트, 청사진 파랑의 단일 상호작용 강조
- 공통 signature: `단지 → 동 → 호` 주소 체인과 조건 변경 즉시 갱신되는 결과 수
- 제외한 기본값: 동일 무게의 드롭다운 나열, 필터 상태가 사라지는 일회성 모달, 필터마다 별도 카드

## 비교할 세 방향

| Variant | 탐색 축 | 강점 | 비용 |
| --- | --- | --- | --- |
| Quick Rail | 사용 빈도와 밀도 | 표의 세로 공간을 가장 많이 보존하고 고빈도 검색이 빠르다 | 상세 조건을 열기 전에는 전체 조건을 한눈에 볼 수 없다 |
| Filter Canvas | 조건 가시성과 직접 조작 | 복합 조건을 기억하지 않고 계속 조정하기 좋다 | 넓은 화면에서도 표의 가로 공간을 사용하며, 좁은 화면에서는 overlay가 된다 |
| Saved Lenses | 반복 업무와 재사용 | “확인 필요”, “광고 없는 가용” 같은 영업 목적에서 즉시 시작한다 | 저장 보기 체계와 개인/사무소 공유 정책이 추가로 필요하다 |

세 안 모두 거래유형, 단지, 동/호, 통합검색, 지역, 건물 유형, 매물 상태, 확인 상태, 가격/보증금, 월세, 전용면적, 입주일, 광고 조건을 실제 24개 샘플 데이터에 적용한다.
