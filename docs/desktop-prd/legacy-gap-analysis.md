# MySpider V2 대비 Desktop 갭 분석 및 로드맵

- 작성일: 2026-07-14
- 근거 자료: `스파이더정리/MySpiderV2-static-analysis.md`, `MySpiderV2-pages-and-CID-analysis.md`, `MySpiderV2-page-ribbons.png` (레거시), apps/desktop 렌더러 전수 코드 조사 (현재)
- 목적: 레거시 MySpider V2의 15개 업무 페이지를 기준으로 현재 desktop 앱의 빠진 기능·끊긴 업무 흐름을 드러내고, 구현 우선순위를 확정한다.

## 1. 요약 결론

현재 desktop 앱은 라우트 기준으로 레거시 대비 대부분의 업무 영역을 이미 커버하며, 매물 목록·매칭·업무·캘린더·계약서·정산은 완성도가 높다. 그러나 **업무 흐름이 실제로 끊기는 지점 3곳**이 있다:

1. **매수요건(구매고객)을 만들 수 없다** — 목록 화면만 있고 생성/수정 UI가 어디에도 없어, 매칭 파이프라인의 시작이 막혀 있다.
2. **매물 상세에서 수정이 안 된다** — 수정 버튼이 빈 함수 stub, "거래 추가" 버튼 disabled.
3. **세입자(Tenant)를 등록 후 관리할 수 없다** — 생성만 가능, 수정·퇴거 처리 UI 없음. 레거시 최대 화면(입주고객)의 핵심인 세대별 점유 관리가 부재.

그 외 레거시 대비 구조적 갭은 **입주고객(동호수 그리드의 점유 표시 모드)**, **알림판(만기/확인요청 위젯)**, **공동중개망(전면 스텁)**, **CTI(Phase 3 예정대로 부재)**다.

## 3. 횡단(페이지 외) 갭

| 항목 | 레거시 | 현재 | 판단 |
|---|---|---|---|
| 탭/멀티윈도우 | MDI + 문서 분할/플로팅 | 브라우저형 탭 + detach 드래그로 새 창 분리 + 창 간 쿼리 무효화 | **현재가 우월** — 추가 작업 불필요 |
| 실시간 동기화 | 평문 커스텀 TCP | socket.io + Clerk 토큰 인증 | 현재가 우월. 이벤트 종류만 확장 여지 |
| 트레이 / 자동업데이트 | 있음(무검증 HTTP — 반면교사) | 없음 | PRD Phase 1 범위(electron-updater + S3). 배포 시점에 필요 |
| 고정비(expenses) | — | 목록만, **등록/수정/삭제 UI 없음** | PRD 5.6 "한번 등록→매월 자동 반영" 흐름이 막혀 있음 |
| 사이드바 비노출 라우트 | — | `/inbox`, `/network`, `/ai-operations`가 사이드바에 없음 | inbox는 노출 검토 |
| ai-operations | — | 정적 소개 페이지 (Codex 연동은 메인 프로세스에 구현됨) | Phase 2 |

## 4. 레거시에서 배울 것 / 피할 것

**배울 것 (사용자가 익숙한 UX):**
- 전 사무소 데이터 로컬 캐시 + 즉시 필터 (현재 listing-intake가 유사하게 달성)
- 상세 사이드패널이 포커스 행을 따라다니는 패턴 (퀵시트로 유사 구현됨)
- 통화기록에서 고객·매물·문서·일정으로 이어지는 연결 탭
- 입주고객 그리드: 한 화면에서 단지 전체의 점유 상태를 색으로 파악

**피할 것 (분석에서 확인된 결함):**
- 표시/닫기만으로 저장이 일어나는 UI 부작용 (팝업 열람이 데이터 갱신, 수신 팝업이 자동 SMS 발송)
- 평문 TCP·하드코딩 자격증명·무검증 HTTP 업데이트
- 화면 코드에 API 호출·비즈니스 로직·인쇄가 뒤엉킨 모놀리식 폼

## 5. 우선순위 로드맵

### P0 — 끊긴 업무 흐름 복구 (즉시)

| 순번 | 작업 | 범위 | 근거 |
|---|---|---|---|
| P0-1 | **매수요건 생성/수정/상세** | buyer-requirements에 생성·수정 다이얼로그(또는 상세 화면), 연락처 상세 매수요건 탭에서 생성 진입 | 매칭 파이프라인 시작점. 레거시 손님알림의 등록 기능 대응 |
| P0-2 | **매물 상세 수정 + 거래 추가** | $id 헤더 수정 버튼 구현(Property·Listing 편집), ListingsSection의 거래 추가 활성화 | 등록 후 수정 불가는 운영 불가 수준 |
| P0-3 | **세입자 관리** | Tenant 수정/퇴거(상태 전이)/삭제 UI — 유닛 상세 다이얼로그와 매물 상세 TenancySection에서 | 등록만 되고 만기·퇴거 처리 불가 |

### P1 — 레거시 킬러 화면 대응 (다음)

| 순번 | 작업 | 범위 | 근거 |
|---|---|---|---|
| P1-1 | **입주고객 모드 (sites 배치표 확장)** | 배치표에 표시 모드 토글(매물/상담 ↔ 점유): 셀별 소유자/세입자/공실/임대만기 색상, 셀에서 바로 세입자 등록·수정, 만기 임박 하이라이트 | 레거시 최대 페이지. Site→Dong→Unit 체인과 Tenant 데이터가 이미 있어 UI 작업 위주 |
| P1-2 | **알림판 위젯 강화** | 대시보드에 임대만기(N일 내), 광고 재게재 필요, 확인 오래된 매물 위젯 추가. 각 위젯 → 해당 화면 필터 링크 | 레거시 알림판 핵심 위젯. 데이터·API 이미 존재 |
| P1-3 | **고정비 등록/수정 UI** | expenses에 CRUD 다이얼로그 | 캐시플로우 순이익 계산의 입력값 |

### P2 — 전략 기능

| 순번 | 작업 | 범위 | 근거 |
|---|---|---|---|
| P2-1 | **공동중개망 MVP** | 서버 network 모듈 + UI: 방 생성/참여, 매물 공유(마스킹), 문의 수락/거절. 채팅은 후반 | PRD 킬러피처. 규모가 커서 P0/P1 이후 착수 |
| P2-2 | 연락처 관계 편집 | ContactRelation 추가/수정/삭제 UI | 레거시 고객관리 대응 |
| P2-3 | 계약서 서식 검증·확장 | 실사용 서식 인쇄 정합성 점검, 필요 템플릿 추가 | 30종 통합 엔진의 실전 검증 |
| P2-4 | 활동로그 뷰어 | ActivityLog 조회 화면 (직원별/엔티티별) | 레거시 작업로그조회 대응 |

### P3 — Phase 3+ 유예

- **CTI/마이콜 팝업·발신** — cti-bridge와 함께 (PRD Phase 3 계획 유지)
- **트레이·자동업데이트** — 배포 준비 시점에
- **쪽지관리** — 도입 보류 (네트워크 채팅으로 흡수 검토)
- **ai-operations 실동작 화면** — Phase 2 내부 AI 챗과 함께
