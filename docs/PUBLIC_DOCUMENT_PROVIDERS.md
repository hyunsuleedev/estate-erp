# 공적장부·등기사항증명서 연동

## 현재 구현 범위

공적장부 요청은 공급자와 출력 형태를 분리한다.

| 문서 | 공급자 | 출력 | 비용 | 현재 처리 |
|---|---|---|---:|---|
| 건축물대장 | 국토교통부 건축물대장정보 서비스 | 구조화 JSON | 무료 | API 키 설정 시 자동 조회 |
| 토지·임야대장 | VWorld 국가공간정보 | 구조화 JSON | 무료 | API 키 설정 시 자동 조회 |
| 지적도·임야도 | VWorld 연속지적도 | GeoJSON 계열 응답 | 무료 | API 키 설정 시 자동 조회 |
| 토지이용계획 | VWorld 국가공간정보 | 구조화 JSON | 무료 | API 키 설정 시 자동 조회 |
| 등기사항증명서 | 인터넷등기소 또는 계약 벤더 | PDF | 열람 700원 / 발급 1,000원 | 요청 생성 후 PDF URL 연결 |
| 대지권등록부 | 발급 기관 | PDF | 기관 정책 | 요청 생성 후 PDF URL 연결 |

공공 API의 구조화 응답은 관공서가 발행한 증명서 PDF를 대신하지 않는다. 계약 심사나
제출용 문서가 필요하면 발급용 등기사항증명서 PDF를 별도로 보관해야 한다.

## 환경 변수

```dotenv
PUBLIC_DATA_SERVICE_KEY="공공데이터포털 일반 인증키"
VWORLD_API_KEY="VWorld 인증키"
VWORLD_API_DOMAIN="https://서비스에서 등록한 도메인"
REGISTRY_PROVIDER="manual"
```

`REGISTRY_PROVIDER`는 `manual`, `tilko`, `hyphen`, `codef`, `coocon` 중 하나다. 현재
자동 등기 커넥터는 공급자 계약·심사·테스트 계정이 없으므로 활성화하지 않는다. 값을
선택해도 공급자 전용 커넥터가 추가되기 전까지는 안전하게 수동 PDF 연결로 폴백한다.

## 등기 공급자 후보

| 후보 | 공식 자료에서 확인한 범위 | 판단 |
|---|---|---|
| 하이픈 | 주소 검색, 열람/발급, 소유자 검증, 주요 등기 필드 및 PDF Hex 반환을 공개 상품 페이지에 명시 | 공개 사양이 가장 구체적이므로 1차 PoC 후보 |
| CODEF | 인터넷등기소의 부동산 등기부등본 발급, 발급/열람 이력 등 지원을 공식 소개서에 명시 | 기존 CODEF 사용 경험이 있으면 유력 후보 |
| 틸코 | 등기부 열람/발급 XML 기능과 인터넷등기소 변경 대응 공지를 제공 | 기존 검토 후보, 안정성·운영 SLA 확인 필요 |
| 쿠콘 | 부동산 등기부 API를 업무 자동화 사례로 소개 | 실제 요청/응답·가격·발급 PDF 범위는 영업 확인 필요 |

## 운영 전 남은 작업

1. 공공데이터포털·VWorld 키를 발급하고 운영 도메인을 등록한다.
2. S3/R2 비공개 업로드 API를 붙여 사용자가 URL을 복사하지 않고 PDF를 직접 올리게 한다.
3. 하이픈 또는 CODEF 테스트 계정을 받아 주소 검색 → 결제 견적 → 열람/발급 → PDF 저장
   전 과정을 공급자 어댑터로 구현한다.
4. 현재 프로세스 내부 비동기 실행을 Redis/BullMQ 워커로 옮겨 다중 인스턴스 재시도와
   장애 복구를 보장한다.
5. 공급자 원문과 파싱 결과의 보관기간, 접근 로그, 개인정보 처리 정책을 확정한다.

## 보안 원칙

- 인증키가 포함된 공급자 URL을 DB, 로그, 프런트엔드에 저장하지 않는다.
- 문서 URL은 HTTP(S)만 허용하며 운영에서는 만료형 비공개 URL을 사용한다.
- 모든 공적장부 레코드는 `office_id`로 격리하고 변경 이력을 남긴다.
- 등기 조회 데이터는 계약 검토 보조 정보이며 권리관계의 최종 판단은 최신 발급 원문으로 한다.
