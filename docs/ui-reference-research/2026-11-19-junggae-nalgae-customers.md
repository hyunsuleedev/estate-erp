# 참좋은중개날개 손님관리 기능 해설

2026-11-19 조사. 대상은 상단 ‘손님관리’로 여는 `/app`의 홈, 폴더·손님 목록, 손님 상세와 그 안에서 여는 창이다. 다른 메뉴로 넘어가는 기능은 손님관리에서 무엇을 넘기고 어디로 이동하는지까지 설명한다.

**추가로 직접 열어 본 경로.** 별도 읽기 전용 브라우저 세션에서 손님 이름을 검색하고 기존 테스트 손님 한 명을 열었다. 검색 결과에 손님과 파일 본문 일치가 함께 나타났다. 상세에는 연락처·컨택일·폴더, 매물 역할, 할 일 3건, 포스트잇, 계약·중개보수 2건, 메모창고 메모 영역, 분류별 파일 4개가 보였다. 이 숫자는 해당 테스트 손님의 예시다. 더보기에서 ‘브리핑한 물건 추가’를 열어 아파트·빌딩 선택, 빌딩 검색 및 상태·거래·면적 필터와 다중 선택을 확인하고 닫았다. 전화 버튼의 확인창도 확인 후 취소했다. 저장·공유·발신·삭제는 실행하지 않았다. 브라우저에서 로드한 손님관리 주 번들 식별자는 `0qvte4_g0d0ht.js`였다.

**읽는 순서.** 먼저 홈에서 어떤 손님을 열지 찾고, 상세에서 그 사람이 *누구인지*, *어떤 물건을 보여줬는지*, *다음에 무엇을 하기로 했는지*를 확인한다. 계약·보수와 자료 보관도 이 상세에서 처리한다. 화면에 다른 업무로 가는 버튼이 있다고 해서 그 업무가 전부 손님별로 저장되는 것은 아니다. 예를 들어 채팅의 단위는 폴더이고, 창고 메모는 원본 한 건에 대한 연결이고, 기존 할 일 가져오기는 업무의 귀속을 옮기는 동작이다.

## 손님 상세에서 실제로 무엇이 연결되는가

아래는 배포된 브라우저 코드의 화면 분기와 저장 요청을 따라간 결과다. 고객 레코드, 장부 행, 매물 역할, 폴더 대화방은 서로 다른 단위를 쓴다. 아래 저장·삭제·공개 결과는 배포 코드에 구현된 동작이다. 직접 조작한 범위는 문서 첫머리에 적었다.

| 상세에서 하는 일 | 기록이 귀속되는 곳 | 직원에게 중요한 효과 |
|---|---|---|
| 표시 이름·당사자·컨택일 변경 | 현재 손님 | 이름을 고치면 현재 대표 표시로 선택된 당사자의 이름이 바뀔 수 있다. |
| 브리핑한 물건 기록 | 손님의 포스트잇 배열 | 방문·소개 당시 선택한 물건이 글로 남는다. |
| 소유자·임차인 연결 해제 | 매물의 해당 역할 | 손님과 특정 물건의 특정 역할만 해제한다. |
| 이전 할 일 가져오기 | 기존 업무의 손님 ID | 원래 다른 손님 소속이던 업무도 이동한다. |
