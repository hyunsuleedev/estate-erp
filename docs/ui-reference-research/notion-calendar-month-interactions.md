## 후속 보완: 스크롤의 걸리는 감각

자유 스크롤만 적용되어 주·월 경계에서 정렬되는 감각이 빠져 있었다. 설치된 Notion Calendar의 실제 computed style과 기존 REA 캡처의 `grid-readable/App-BsElY8Ua.js`를 다시 확인했다. Notion은 컨테이너에 `scroll-snap-type: y mandatory`, 각 주에 `scroll-snap-align: start`, 1일을 포함하는 주에 `scroll-snap-stop: always`를 사용한다. 실제 휠 입력 후 약 200ms 시점에는 주 행 경계로 정렬됐다. 큰 휠 입력은 여러 달을 지나갈 수 있으므로 한 번에 한 달만 이동시키는 페이지 전환은 아니다.

ERP에도 같은 스냅 규칙을 적용했다. 드래그, 화면 크기 변경, 날짜 탐색, 주 버퍼 재배치 중에는 스냅을 잠시 끄고 위치 반영 후 복구한다. 드래그가 이어지는 동안에는 재배치 이후에도 꺼진 상태를 유지하여 가장자리 자동 스크롤과 충돌하지 않는다.

실제 Electron에서 작은 휠 입력, 월 경계 정렬, 역방향 입력, 정렬 중 추가 입력, 장거리 스크롤, 드래그 중 스냅 중지, Esc 후 복구, 오늘 이동, 새로고침, 버퍼를 두 번 넘는 가장자리 드래그까지 11개 항목을 확인했다. 이번 검수에서는 일정을 생성하거나 변경하지 않았다. 데스크톱 타입 검사와 수정 파일의 ESLint도 통과했다.

## 후속 수정: MacBook 트랙패드 관성에서 여러 달이 넘어가는 오류

일반 CDP 휠 입력만으로는 재현되지 않았다. macOS CoreGraphics의 연속 스크롤·손가락 입력 종료·관성 시작/진행/종료 단계를 실제 Electron 창에 전달하자, 총 138px 입력이 52주 이동으로 증폭되는 회귀 테스트가 실패했다. 이는 물리적인 손가락 조작 검수가 아니라 운영체제의 관성 단계를 포함한 네이티브 입력 재현이다.

원인은 관성 중 주 버퍼를 재배치하면서 `scrollTop`을 보정한 것이었다. 브라우저가 기존 관성/스냅의 목표 좌표를 계속 따라가면서, 재배치한 거리만큼 이동이 반복됐다. 일반 스크롤의 버퍼 재배치를 네이티브 `scrollend` 뒤로 옮겼다. 포인터 드래그의 가장자리 자동 스크롤은 관성이 없으므로 기존처럼 즉시 재배치한다. 주 경계 스냅과 월 첫 주의 정지 규칙은 유지한다.

- 같은 138px 네이티브 입력이 수정 후 앞/뒤 각각 2주에서 멈췄다. 추가 대기 후에도 이동하지 않았고, 주 경계 정렬과 22주 버퍼 복원이 확인됐다.
- 일반 휠 ±90px는 각각 한 주 이동했다. 버퍼를 넘는 가장자리 드래그, Esc 취소 후 스냅 복구, 오늘·이전·다음 탐색, 새로고침 후 위치 복원을 실제 Electron에서 확인했다.
- 캘린더 관련 테스트 17개, 데스크톱 타입 검사, 수정 컴포넌트 ESLint 통과. 이번 검수는 일정 데이터를 생성·변경하지 않았다.
