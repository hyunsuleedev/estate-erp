# 부동산이지 페이지별 업무와 구현 구조

2026년 11월 19일 · Chrome 로그인 화면과 같은 날 배포된 프런트엔드 기준.

**업무 흐름**　원장에서 호실을 찾고 소유·점유 관계를 확인한다. 매도·임대 의뢰는 매물로, 매수·임차 의뢰는 고객 의뢰로 접수한다. 계약 후에는 잔금·신고일과 매출을 각각 관리한다.

**확인 범위**　실화면은 로그인한 Chrome에서 본문을 확인한 페이지다. 배포 코드 분석은 라우터의 중첩 경로, 도움말, 연결된 JavaScript 파일의 표시 문구를 근거로 한다. 쓰기·발급·결제 결과, 서버 데이터 모델과 권한은 확인하지 않았다.

**구현**　공통 HTML이 Vite 모듈과 PWA 서비스 워커 등록 파일을 로드한다. 번들에 Vue와 Vue I18n 코드가 있고 라우터가 업무별 화면을 동적으로 불러온다. 공통 레이아웃 안에 목록·상세·탭을 중첩한다. 가계약·계약 목록, 단지 안팎의 N 모니터링, 내부·공유 계약서는 각각 같은 화면 파일을 쓴다. [배포 진입 파일](https://bdseasy.com/assets/index-7729270e.js)

**REA 검증**　일정 관리, 고객 의뢰 목록, 계약 목록의 배포 모듈 세 개를 REA JavaScript application analyzer로 정적 분석했다. 예를 들어 일정 관리 모듈에서 공통 진입 파일을 가져오는 정적 참조가 검출됐다. 세 파일만 넣은 분석에서는 외부 모듈 참조가 미해결로 표시된다. 아래 전체 경로표는 별도로 진입 파일의 라우트 선언과 동적 import 대상을 대조해 작성했다.
