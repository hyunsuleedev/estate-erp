# Notion Calendar 일정 편집 카드 적용

2026-11-11, 설치된 Notion Calendar와 Estate ERP의 실제 개발용 Electron 앱을 비교했다. 운영 배포 결과가 아니다.

## 관찰

Notion의 새 일정 화면은 캘린더 위 오른쪽에 좁은 편집 카드를 표시한다. 배경을 어둡게 덮지 않고, 헤더의 고정 버튼을 누르면 캘린더 옆 오른쪽 패널로 바뀐다. 제목, 시간 범위, 날짜, 종일 옵션, 설명 등의 필드가 세로로 이어진다. 실제 앱에서 고정/해제를 확인한 뒤 처음 상태로 되돌렸다. Notion에 새 일정을 저장하거나 기존 일정을 수정하지는 않았다.

기존 ERP는 중앙 모달에서 제목·유형·색상·날짜·CRM 연결을 한꺼번에 입력하는 큰 폼이었다.

## 적용

- `-event-dialog.tsx`의 `EventEditor`는 배경을 가리지 않는 352px 편집 카드다. 오른쪽 고정/해제 시 작성 내용이 유지된다.
- 제목에 자동으로 포커스하고 시간과 날짜를 분리했다. 입력칸 테두리를 줄이고 CRM 연결은 필요할 때 펼친다. 연락처·매물·매물 조건·매칭·거래 연결, 유형·색상, 삭제 권한은 유지한다.
- 월 보기의 날짜 범위와 주/일 보기의 시간 범위가 편집기로 전달된다. 작성 중인 제목과 날짜·시간은 캘린더에 미리 표시한다. 이 미리보기는 서버에 저장된 일정이 아니다.
- 캘린더 스크롤과 바깥 클릭은 편집을 닫지 않는다. 다른 빈 날짜를 다시 선택하면 제목·설명·연결은 유지하면서 날짜를 바꾼다.
- 종일 토글을 되돌리면 이전 시간 범위를 복구한다. 종료 없음은 수정 API에 `null`을 전달한다.
- 저장 버튼 또는 Cmd/Ctrl+Enter로 저장하고, 실패하면 입력을 유지한다. Esc/닫기는 작성 중인 미리보기를 제거한다. 자동 저장은 도입하지 않았다.
- 고정 편집창에서 월 보기의 일곱 요일이 보이도록 최소 폭을 조정했다. 저장 알림이 고정 패널의 저장 버튼을 덮는 문제는 해당 알림을 상단으로 옮겨 수정했다.

## 검수

실제 Electron에서 20개 확인 항목이 통과했다. 범위 드래그, 제목 포커스와 검증, 고정·해제, 바깥 클릭, 작성 내용 보존, CRM 연결 검색과 Esc, 주/월 미리보기, Cmd+Enter 저장, API 재조회, 저장 요청 실패 주입과 재시도, 종료 제거, 삭제, 종일/시간 전환, Tab 이동, 캘린더 스크롤을 포함한다.

검수용 일정은 UI에서 생성·수정·삭제했고, API에서 검수 접두사 잔여 일정 0건을 확인했다. 날짜 미리보기 3개와 기존 월/시간 그리드 14개 단위 테스트가 통과했다. 데스크톱 타입 검사 및 편집기·미리보기·페이지·신규 테스트 파일의 ESLint가 통과했다. 시간 그리드 파일 전체 ESLint에는 기존 non-null assertion 경고 10개가 남아 있고 오류는 없다.
