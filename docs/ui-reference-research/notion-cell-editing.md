# Notion 셀 입력과 매물관리 표 비교

2026-11-12. 현재 열린 Notion `작업 트래커 → 모든 작업`과 실제 로컬 Electron 매물관리 표를 관측했다. 이번 작업은 분석이며 제품 코드는 변경하지 않았다.

후속 [REA 코드 심층 분석](./notion-cell-editing-rea.md)에서 실제 편집기 번들과 저장·닫기·키보드 경로를 추적했다. 아래는 최초 화면 관측 범위이며, 상태의 현재 값 표시에 관한 설명은 후속 코드/화면 검증 결과로 정정했다.

## 우선 개선할 부분

1. **선택한 셀과 편집하는 셀을 일치시킨다.** 우리 앱에서 첫 행의 동 셀을 선택한 뒤 두 번째 행 메모를 편집하면, 파란 테두리는 여전히 첫 행 동 셀에 남는다. 표의 `focusedCell`과 `CellEditProvider`의 편집 셀이 따로 관리되는 문제가 실제 화면에서 재현됐다.
2. **편집창이 원래 셀에서 자연스럽게 이어지도록 한다.** Notion도 떠 있는 편집창을 쓰지만 글자 크기·줄 높이·시작 위치를 유지한다. 우리 편집창은 테이블의 표시 텍스트와 폰트/패딩이 달라지고, 화면 끝에서 왼쪽으로 보정되며 다른 열을 덮을 수 있다. 원래 셀의 위치와 보이는 폭을 우선하고 그림자를 가볍게 한다.
3. **메모는 여러 줄 입력과 내용에 맞는 높이를 제공한다.** 현재 우리 메모는 `input` 한 줄이다. Notion의 긴 설명은 편집 시 두 줄로 펼쳐지며 아래 행의 높이를 밀지 않는 오버레이가 된다. 우리 메모는 자동 높이 textarea와 적절한 최대 높이/내부 스크롤이 적합하다.
4. **선택과 키보드 편집을 연결한다.** Notion에서 편집창을 Esc로 닫은 뒤 Enter로 같은 셀 편집을 다시 열었고, 텍스트 편집 중 Tab은 옆 상태 셀의 선택 테두리로 이어졌다. 우리 앱은 표에 포커스가 있으면 Enter가 상세 열기이고 편집 버튼에 있으면 Enter가 편집이다. 편집 가능한 셀의 Enter/F2를 통일하고 상세 열기는 이미 추가한 열기 버튼으로 구분하는 방향을 제안한다.
5. **상태 선택기는 맥락을 유지한다.** Notion은 셀 위치에서 현재 상태 칩과 검색 입력, 상태 그룹을 함께 보여 준다. 검색에 `진행`을 입력하면 목록이 `진행 중`으로 좁혀졌다. 우리 앱 공통 컴포넌트에는 현재 값 표시 기능이 있지만, 후속 조사에서 실제 매물상태의 값 연결이 빠져 있음을 확인했다. 먼저 이 연결을 수정하고 키보드 탐색을 보강하되, 선택지가 네 개인 매물상태에 검색까지 그대로 추가할 필요는 없다. 거래 상태 전환의 기존 확인 절차는 유지한다.

## 실제 관측

### Notion

- 현재 대상: `작업 트래커 | 모든 작업`, CDP target `B7F731F4880E79737C3DB6B8E77AE69E`.
- 제목 텍스트 한 번 클릭 → 셀에 붙은 편집창과 caret. 기존 값은 입력하거나 변경하지 않았다.
- 제목 편집기: 폭 276px, 높이 38px, 모서리 6px. 내용은 14px, 줄 높이 21px, 흰 배경. 얕은 여러 겹 그림자.
- 설명 편집기: 폭 267px, 높이 58px. 기존 긴 문장이 42px 높이의 두 줄 콘텐츠로 펼쳐졌다.
- Esc → 편집창 닫힘. Enter → 같은 제목 편집 재개. 변경하지 않은 제목에서 Tab → 오른쪽 상태 셀 선택으로 이동.
- 상태 선택: 현재 `Done` 칩과 검색, 할 일/진행 중/완료 그룹. 검색만 입력하고 선택하지 않은 채 Esc로 닫았다.
- 최종 표의 세 행 값이 최초 관측 값과 같고 열린 dialog가 없는 것을 확인했다.
- 셀 선택의 파란 테두리는 실제 화면에서 확인했다. 범위 선택, 복사/붙여넣기, 저장 속도, Undo, 변경 후 Esc의 되돌리기 의미는 이번에 검증하지 않았다.

### 우리 앱

- 실제 Electron에 agent-browser로 연결해 메모와 가격을 더블클릭하여 편집창을 열고 Esc로 닫았다. 값을 수정하거나 저장하지 않았다.
- 메모는 13px 한 줄 `input`; 관측 편집창 높이 42px. 그림자는 `0 12px 28px rgba(15,23,42,0.2)`.
- 첫 행 동 셀 선택 → 두 번째 행 메모 편집에서 선택 테두리가 첫 행 동 셀에 남는 현상을 별도로 재현했다.
- 상태 셀 클릭으로 활성/보류/거래중/종료 선택기가 열리는 것을 확인하고 선택 없이 닫았다.

## 코드에서 확인한 범위

- `property-listings-table.tsx`: 표의 선택 셀 좌표와 Enter 상세 열기.
- `cell-editor.tsx`: 별도 편집 셀 저장소, 편집 버튼 클릭의 `stopPropagation`, Enter/Space/F2 편집 진입. 이 분리로 표의 선택 위치가 편집 진입과 함께 갱신되지 않을 수 있다.
- 같은 파일: 셀 크기보다 12px 넓은 floating editor, 고정된 입력 높이와 viewport 경계 보정. 텍스트와 숫자가 동일한 한 줄 input을 사용한다.
- 기존 Enter 저장, Tab/Shift+Tab 이동, Esc 취소, IME 조합 중 Enter 무시 로직은 이미 존재한다. 없는 기능으로 보고 새로 만드는 대신 선택 모델에 연결해야 한다.
- 외부 클릭은 현재 `onCancel(false)`에 연결된다. 저장 함수는 mutation 호출 후 편집창을 닫고 서버 응답 후 목록을 다시 조회한다. 입력 초안 보존, 저장 중 표시, 실패 시 복구는 별도 개선 후보이며 이번 조사에서 실제 저장/오류를 발생시켜 검증하지 않았다.
