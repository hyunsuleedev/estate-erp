# 이실장 업무 화면과 프런트엔드 코드 조사

2026년 11월 19일, 로그인한 별도 Chrome 조사 창에서 홈과 업무·지원 메뉴 21개 경로를 열었다. 고객과 계약은 목록에 표시된 상세 링크를 따라 두 화면을 추가로 확인했다. 페이지에서 실제로 로드한 이실장 도메인의 외부 JavaScript 62개를 REA 6.8.0으로 분석했다. 다음의 함수명은 해당 배포본에서 확인한 이름이다.

## 고객 한 사람을 기준으로 보는 업무

| 화면 | 중개사가 해결하는 일 | 화면과 코드에서 확인한 동작 |
| --- | --- | --- |
| 내 고객 · `/customer/list` | 연락할 사람을 찾거나 고객 명부를 정리한다. | 거주지·고객유형·문의유형·담당자·이름(별칭)·상호·연락처를 다룬다. 목록의 고객을 누르면 해당 행의 고객 번호로 상세를 연다. 엑셀 가져오기에는 중복 연락처 확인과 병합 선택 화면이 있다. `customerList.js`의 `ajaxFileUpload`는 서버가 반환한 저장·중복·실패 목록을 구분한다. 저장된 항목이 있으면 완료 표시 후 새로고침하는 분기가 앞서므로, 한 파일에 성공·중복이 섞였을 때 중복 창까지 뜬다고 단정하기 어렵다. |
| 고객 상세 · `/customer/info` | 한 사람과 다음에 무엇을 이야기할지 준비한다. | 실제 고객 상세에서 고객정보·일정·상담내역·희망 물건 조건을 확인했다. 일정 코드는 알림 추가·제거를, 상담 코드는 단지·동·호와 소유형태 선택을, 희망조건 코드는 요구조건 추가·저장을 담당한다. 문의한 부동산을 기록하는 일과 앞으로 원하는 부동산의 조건을 적는 일에 별도 입력 처리가 있다. |
| 상담내역 · `/customer/counselList` | 여러 고객의 상담 기록에서 과거 문의를 찾아 이어받는다. | 이름·연락처·상담내용 통합 검색과 문의물건·문의유형·상담일·상담유형 필터가 보인다. 결과는 상담일시·고객정보·상담내용·상담자 기준이다. `counselList.js`의 `detailMoveOrLayerPop`은 선택 행의 상담·고객 번호를 읽고 상담 내용을 폼에 복원한다. 수정 시 고객명·전화 입력을 잠근다. 같은 고객의 별도 상담 건을 구분하는 근거다. |
| 맞춤매물 · `/customer/matchedList` | 어떤 고객의 희망조건에 새 후보가 들어왔는지 확인한다. | 목록에서 고객조건 옆에 신규매물·총매물이 표시된다. 거래유형·매물종류·지역·단지·면적·예산을 비교할 수 있다. 조건 폼에는 월세 보증금과 월차임의 별도 범위, 방·욕실 수, 층·향·주차·관리비 등의 입력이 있다. `matchedList.js`는 새 조건을 열 때 이전 조건 번호와 입력을 초기화하고 멤버십을 확인한다. 계산에 사용한 가중치, 신규 판정 시점, 후보가 0건인 이유는 확인되지 않았다. |
| 일정관리 · `/ai/schedule` | 날짜를 기준으로 약속과 할 일을 찾는다. | 홈의 ‘오늘 할일’에서도 일정을 시작할 수 있다. 일정 화면은 `home/scheduleModal.js`를 로드하고, 고객 상세에는 별도 `info/schedule.js`가 있다. 고객 검색·일정 조회·시간 선택·알림 설정 처리가 확인된다. 어느 화면에서 시작하느냐에 따라 날짜 또는 고객을 먼저 정할 수 있다. |

## 호실에서 매물과 광고까지

| 화면 | 업무 목적 | 화면과 코드에서 확인한 동작 |
| --- | --- | --- |
| 홈 · `/home` | 오늘 처리할 광고와 연락할 대상을 고른다. | 광고 검증·종료예정 건수, 단지별 신규·삭제·내 매물, 동일매물 수와 그룹 내 순위, 임대차 만기, 당일 일정을 함께 본다. `mainV2Offering.js`에서 광고 상태·모니터링·만기 목록을 별도 함수로 조회한다. |
| 점유상태 · `/field/complex/occupy` | 단지 안에서 현재 누가 어떤 형태로 점유하는지 파악한다. | 동·호별 공급/전용면적, 소유형태, 소유자·거주자, 현재점유형태, 거래가·계약일·등기열람일시를 배치한다. 자가·전세·월세 필터와 관리 호실 추가 진입점이 있다. `fieldFunction.js`에서 지역→단지→동→호 선택을 연결한다. |
| 내 관리 호실 · `/field/complex/hosil` | 사무소가 후속 연락할 호실을 관리한다. | 소유자·거주자 옆에 희망거래가와 희망거래일을 보여준다. 점유 화면과 같은 임장 스크립트를 사용하지만 필터는 매매·전세·월세다. 같은 호실을 현재 사용 상태와 향후 거래 의사라는 두 관점에서 본다. |
| 임장알림 · `/field/alarmStatus` | 추적 중인 단지에서 변동이 일어난 대상을 찾는다. | 동·호·면적·거래조건·계약일·알림일과 등기목적·접수일·발급 항목이 있다. `fieldAlarmStatus.js`가 만기·공지·거래 알림 목록을 구분해 조회한다. |
| 매물장 · `/offerings/list` | 사무소가 관리하는 매물 기록을 검색·선택한다. | 매물번호 검색, 전체 선택, 엑셀 다운로드가 있다. `v2/offeringsList.js`는 기존 주소 선택값을 복원하고 새 검색 시 첫 페이지를 제출한다. 검색·페이징은 같은 폼을 사용한다. |
| 매물광고 · `/offerings/ad_list` | 광고 한 건이 어느 채널에 어떤 검증방식으로 나갔고 다음에 어떤 처리가 필요한지 판단한다. | 노출채널/검증방식·광고상태·등록기간·재광고 열이 있다. DOM에는 광고 이력·실패 사유·의뢰인 수정 요청 영역도 있다. `v2/offeringsAdList.js`에서 일반 수정과 노출 후 수정, 검증실패의 재검증과 결제실패의 재광고, 노출종료와 거래완료가 각각 분기한다. 등록 버튼 하나만으로 설명하기 어려운 운영 화면이다. |
| 네이버 모니터링 · `/monitoring/monitoring` | 동일 매물 그룹 안에서 내 광고의 위치와 다른 중개업소의 광고를 비교한다. | 순위·가격·동·층·면적·등록일·중개업소·동일매물 수를 본다. `monitoring2.js`의 `getSameOffers`는 선택 매물·단지·사무소 식별자로 그룹 목록을 조회하고 응답의 순위를 행에 표시한다. 화면 코드에서 동일매물 판정 공식이나 네이버의 순위 산식을 확인할 수는 없다. |
| 사진관리 · `/ephoto` | 현장 촬영 사진을 주소별로 정리하고 매물 등록에 활용하는 서비스를 안내한다. | 이번 로그인에서 보인 본문은 ‘집찍고’ 소개였다. 휴대폰에서 옮기기, 주소별 자동 정리, 고객에게 사진 요청, 편집, 앱 다운로드를 안내한다. 로드된 `ephoto_content.js`에는 폴더 생성·이름 변경·선택·공유·다운로드 처리가 있다. 이번 화면에서 실제 사진첩이나 공유 결과를 확인한 것은 아니다. |

## 계약과 신청 서비스

| 화면 | 업무 목적 | 화면과 코드에서 확인한 동작 |
| --- | --- | --- |
| 계약 리스트 · `/contract/list` | 계약일·잔금일·만기일, 당사자와 상태를 기준으로 진행 중인 계약을 찾는다. | 소재지·계약서 유형·거래유형·금액·공동중개업소·계약서번호가 보인다. `contract/list.js`의 작성 폼은 유형에 따라 단지·동·호·면적 또는 번지·상세주소를 요구한다. 행의 상세보기는 개별 계약 문서를 연다. |
| 계약 상세 · `/contract/show/…` | 선택한 계약 문서와 그 작성 근거를 함께 다룬다. | 실제 상세 문서에서 공부명·기준 공부명·공부기준 데이터 항목을 확인했다. `contract/contract.js`에는 고객 찾기, 공동 중개업소 추가, 날짜 처리, 공부 데이터 연결이 있다. `contract/common.js`의 `isPropertyAbleContract`는 대상 계약 유형과 버전 2 이상을 함께 확인한다. 공부 관련 코드는 집합·일반건물 구분, 복수 등기 선택, 발급 대기·실패·PDF 표시를 구분한다. 실제 유료 발급·문서 저장은 검증 범위 밖이다. |
| 안심케어 서비스 소개 · `/safecare/service_info` | 등기변동 체크·법률상담·권리보험으로 안내하는 거래 지원 서비스의 내용을 살펴본다. | 홈 배너와 소개 메뉴에서 진입한다. 안심케어 공통 스크립트를 로드한다. 계약별 이용 가능 여부나 보장 범위는 조사하지 않았다. |
| 안심케어 신청 내역 · `/safecare/list` | 신청한 거래를 찾아 진행 자료와 이력을 확인한다. | 신청번호·소재지·거래유형·거래가·계약일·임대차 만료일·잔금일·당사자·신청일시를 함께 본다. `safecare/list.js`에 검색 조건 복원, 등기 이력, 발급 팝업, 이용권 목록·상세 조회가 있다. |
| 아파트아이 · `/customer/apti_intro` | 특정 단지 입주민을 대상으로 하는 광고 상품의 대상과 가입 상태를 확인한다. | 단지·가입기간·판매가·상태·대기 신청일과 노출 사진 항목이 있다. `apti/intro.js`는 이용 목록과 대기 목록을 별도로 조회·렌더링한다. |

## 자료 범위

REA는 JavaScript 62개를 파싱했고 누락 파일과 파싱 오류는 각각 0개였다. 그래프에는 동적 연결과 보존 한도로 해석되지 않은 부분이 있다. jQuery 이벤트와 팝업은 원본 배포 스크립트의 함수 본문을 함께 읽었다. 표에 등장하는 비활성 팝업은 코드와 DOM에 존재하는 기능이며, 실제로 제출하거나 외부 서비스 처리를 완료했다는 뜻은 아니다. 계정관리·결제·외부 제휴 사이트와 개별 뉴스·공지·FAQ 문서 전체는 이번 23개 경로에 포함되지 않는다.
