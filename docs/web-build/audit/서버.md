# 감사: 서버 API 전체 감사 (apps/server/src/modules) — 웹 UI 전 페이지 관점 — partial (6.5/10)

CRM 코어(장소 체인, 매물/의뢰/광고, 연락처, 상담+녹음/STT, 매칭/거래/계약+문서템플릿, 업무/캘린더, 직원, 수수료/캐시플로우/장부, 업체, 공적장부, AI 규칙/제안/인박스, MCP)는 39개 컨트롤러로 충실히 구현되어 있고 품질도 일관적이다. 그러나 PRD의 킬러 피쳐인 공동중개 네트워크 모듈이 서버에 아예 없고(network/notifications/cti/insights 디렉토리가 빈 폴더), 알림 목록 API와 대시보드 집계 API도 없다. 멀티테넌시는 RequestContextMiddleware 전역 적용 + Prisma 확장의 TENANT_SCOPED_MODELS 자동 officeId 주입 + 컨트롤러에서 user.officeId 명시 전달의 이중 방어로 일관성이 높다.

## 구현돼 있는 것 (건드리지 말고 유지/개선)
- 인증: Clerk 기반 외부 로그인 + GET /auth/me, POST /auth/logout (JwtAuthGuard+RolesGuard)
- 장소: sites(overview 포함)/dongs/units/office-sites(search)/regions(provinces/districts/wards/search) CRUD
- 매물: properties, listings(filter-sites, check-status), listing-intakes(map, confirm, status), property-photos(reorder), property-contacts(with-contact), tenants(expiring, with-contact)
- 연락처: contacts(phone-index, search-by-phone, 연관 리소스 서브조회), contact-relations(with-contact)
- CRM: buyer-requirements(due-contacts, status), consultations(recent, with-recording, STT, recordings), matches(stage), deals(stage, cancel), contracts(생성/수정 + 문서/인쇄템플릿/조항템플릿 GET·POST·PATCH + :id/documents)
- 업무: tasks(reorder, bulk-status, bulk-delete), calendar-events CRUD
- 직원: POST /employees(직접 생성), PATCH :id/status(비활성화), :id/role, reset-password(rate limit), :id/performance — owner/manager Roles 가드
- 설정: GET/PATCH /offices/me, PATCH /offices/me/commission-config (owner/manager 전용)
- 재무: finance/cashflow(이번달 수금/지출/순익/6개월 추이), finance/ledger(preset), commission-payments(collect/waive/confirm/tax-invoice/distributions), commission-adjustments(승인 플로우), expenses CRUD
- 광고노트: external-listings(groups, sessions, batch upsert), listing-advertisements, office-advertisements(link-listing-advertisement)
- AI: agent/rules(PATCH :name), proposals(approve/reject), inbox(decide/reject/snooze/comments/revision)
- 업체: service-vendors(연락처 1:N, favorite), partner-brokers, public-documents(status)
- MCP: POST /mcp + api-key 발급/삭제 + OAuth discovery(.well-known)
- 멀티테넌시: RequestContextMiddleware 전역(app.module.ts:116) + PrismaService 확장이 24개 TENANT_SCOPED_MODELS에 officeId 자동 주입(where+data), 컨트롤러도 user.officeId 명시 전달(이중 방어), Site/Dong/Unit/ServiceVendor 등 nullable officeId 모델은 서비스 레벨 OR:[{officeId},{isPublic:true}] 패턴
- 실시간: realtime gateway(listing.join/leave, property.join, listing-intake.join) + Redis adapter

## 갭 (이번 빌드에서 해결할 것, 중요도순)
- 네트워크(공동중개) 모듈 전체 부재 — modules/에 network 디렉토리 자체가 없음. Prisma에는 NetworkRoom/Member/SharedProperty/Inquiry/Message 모델과 tenant-scope 등록까지 있으나 API가 0개. PRD 킬러 피쳐가 서버에서 시작도 안 됨
- 알림 API 부재 — modules/notifications 디렉토리가 빈 폴더. Notification 모델은 tenant-scope에 있으나 목록/읽음/뱃지 카운트 엔드포인트 없음. realtime gateway도 알림 이벤트 미발행
- 대시보드 통계 API 부재 — finance/cashflow가 수금/지출/순익만 커버. 이번달 계약 수, 신규 의뢰(intake/구매조건) 수, 매물/고객 집계를 주는 단일 엔드포인트 없음 → UI가 페이지네이션된 목록을 전부 받아 클라이언트 집계해야 하는 구조
- modules/cti, modules/insights 빈 디렉토리 — 죽은 스캐폴딩 (Phase 계획상 의도일 수 있으나 정리 필요)
- 계약 인쇄/조항 템플릿에 DELETE 엔드포인트 없음 (GET/POST/PATCH만) — 설정 페이지의 템플릿 관리 UI에서 삭제 불가
- ActivityLog 조회 API 없음 — 감사 로그는 자동 기록되지만 읽는 엔드포인트가 없어 직원 활동 추적/감사 UI 구현 불가
- 직원 초대는 이메일 초대 링크 방식이 아닌 사장님 직접 생성+비밀번호 전달 방식만 존재 (loginId 정책상 허용 가능하나 PRD '직원 초대' UX와는 차이)
- auth에 비밀번호 변경(본인) 엔드포인트 없음 — reset-password는 owner/manager가 타인 대상만 가능

- [P0] 네트워크 모듈 전체: POST/GET /network/rooms, POST /network/rooms/:id/join + 멤버 승인/거절(PATCH members/:id), POST /network/rooms/:id/shared-properties (show_* 마스킹 포함) + PATCH/DELETE, POST /network/shared-properties/:id/inquiries + 수락/거절, GET/POST /network/rooms/:id/messages + Socket.io room 이벤트 — 네트워크 페이지(방 목록/방 상세/공유/문의/채팅) 전부가 의존하는데 서버에 0개
- [P0] 알림: GET /notifications(커서 페이지네이션), PATCH /notifications/:id/read, POST /notifications/read-all, GET /notifications/unread-count + realtime 'notification.created' push — 헤더 알림 벨/알림 페이지 구현 불가
- [P1] 대시보드 통계: GET /dashboard/stats (이번달 수금액·수금예정, 이번달 계약(Deal/Contract) 체결 수, 신규 의뢰 수(ListingIntake+BuyerRequirement), 활성 매물 수, 진행 중 매칭/거래 수, 임박 일정·만기 계약 수) — 현재 cashflow는 수금 축만 제공
- [P1] DELETE /contracts/print-templates/:templateId, DELETE /contracts/clause-templates/:templateId — 설정>문서 템플릿 관리 화면의 삭제 버튼
- [P2] GET /activity-logs (entityType/entityId/userId 필터) — 직원 활동 추적·엔티티 변경 이력 패널
- [P2] PATCH /auth/me/password (본인 비밀번호 변경) — 설정>내 계정 화면
- [P3] 직원 초대 링크 플로우 (POST /employees/invitations) — 현재는 직접 생성 방식만이라 UI는 생성 폼으로 우회 가능
