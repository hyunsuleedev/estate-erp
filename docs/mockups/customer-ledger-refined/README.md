# 고객 원장 — 기존 구조 개선 시안

`index.html`을 브라우저에서 직접 엽니다. 설치·서버·외부 라이브러리가 필요 없는 독립 HTML입니다. Electron 데스크톱 앱을 위한 시안으로, 모바일 전용 배치는 포함하지 않습니다.

## 이번 변경

첫 시안의 3열 목록과 상시 상세 패널에서 돌아와, 현재 `/customers` 코드의 상단 탭·검색·필터 → 열 제목 → 고객 묶음 → 구함/내놓음 의뢰 구조를 기준으로 만들었습니다. `DESIGN.md`의 흰 배경, 웜 뉴트럴 보조 영역, 작은 상태색을 사용합니다. 실제 Electron 화면에 적용한 변경은 아닙니다.

- 전체 / 구함 / 내놓음 탭과 검색, 지역·거래·상태·담당자 필터 유지
- 최소·최대 예산, 월세, 평형, 매칭, 등록일 열 유지
- 고객명·금액을 강조하고 상담·위치·조건을 보조 정보로 배치
- 기본 정렬은 현재 코드와 같은 최근 등록순
- 작은 정렬 메뉴에 최근 등록순 / 최근 상담순 / 다음 연락일순 / 이름순 제공
- 예산·월세·평형·매칭 정렬은 메뉴의 추가 영역과 열 제목에서 사용
- 숫자 열은 내림차순 → 오름차순 → 해제, 이름 열은 오름차순 → 내림차순 → 해제
- 정렬 해제는 예시의 기본 등록일 내림차순으로 복귀하며 정렬 표시는 제거
- 마지막 정렬 선택은 브라우저에 저장. 검색·필터 초기화 및 의뢰 추가 시 유지
- 헤더와 본문이 한 표 안에서 함께 가로 스크롤
- 고객별 접기·펼치기, 전체 선택, 상담 기록 추가, 구함 의뢰 추가 동작

## 예시 데이터와 범위

고객 9명, 의뢰 11건으로 시작합니다. 모든 고객·연락처·조건은 가상이며 예시 연락 일정은 2026-09-15 기준입니다. 추가한 의뢰와 상담은 입력 시점의 날짜를 씁니다. 변경 데이터와 정렬은 `estait-ledger-refined-v1` 접두사의 localStorage에만 저장합니다.

고객 안에서 현재 필터에 맞는 의뢰를 사용하여 최소값 열은 최솟값, 최대값 열은 최댓값, 매칭은 합계로 고객 묶음을 정렬합니다. 값이 없으면 마지막에 표시합니다. 이 집계 방식은 HTML 시안용이며 실제 서버와의 동작 동일성을 보장하지 않습니다. 최근 상담순과 다음 연락일순 또한 예시 데이터로 동작하는 제안 기능입니다.

주변 메뉴는 정적인 배치 미리보기입니다. 매칭 버튼은 건수 요약만 펼칩니다. 실제 매칭 데이터, CRM API, 전화 발신은 연결되어 있지 않습니다. 추가 폼은 새 가상 고객과 구함 의뢰를 생성하며 기존 고객 연결 기능은 포함하지 않습니다.

## 브라우저 확인

Ego Browser에서 실제 클릭과 입력으로 확인했습니다.

- 이름 정렬 후 새로고침해도 순서와 메뉴 표시 유지
- 최대예산 내림차순(김민준 먼저) → 오름차순(오수빈 먼저) → 해제(최유진 먼저)
- 이름 검색, 결과 없음, 초기화
- 이민호 필터 4명, 보류 필터 1명, 내놓음 탭 5명
- 가격 8억 이하 필터 4명
- 모두 접기/펼치기, 표시 고객 전체 선택/해제
- 상담 저장 후 새로고침, 최근 상담순과 다음 연락일순
- 구함 의뢰 추가 후 정렬 유지 및 새로고침 후 데이터 보존
- 1024px에서 표 가로 스크롤 후 열 제목과 본문의 위치·너비 일치

미리보기 과정에서 입력한 가상 고객과 상담이 검수 브라우저에 남아 있을 수 있습니다. 파일의 초기 데이터는 9명이며 별도 브라우저에서 처음 열면 초기 데이터가 표시됩니다.
