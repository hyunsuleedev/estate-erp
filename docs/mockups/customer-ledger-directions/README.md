# 고객원장 스타일 3안

`index.html`을 브라우저에서 직접 엽니다. Electron 데스크톱의 고객원장 한 구역을 비교하기 위한 독립 HTML입니다. 원장 전체나 모바일 화면의 구현이 아닙니다.

| 안 | 달라지는 축 | 잘 맞는 경우 | 비용 |
| --- | --- | --- | --- |
| Precision | 13px 고객명, 36px 의뢰 행, 고정폭 숫자, 작은 반경, 열 구분 | 많은 고객과 금액을 빠르게 비교 | 표현은 가장 담백함 |
| Editorial | 24px 명조 고객명, 46px 의뢰 행, 상담을 별도 열에 배치, 넓은 여백, 수평선 | 고객·상담 중심으로 읽기 | 같은 높이에 보이는 고객 수가 적음 |
| Workspace | 짙은 탐색부, 밝은 작업 영역, 15px 고객명, 48px 의뢰 행, 큰 조작 구획 | 탐색과 작업 영역을 확실히 구분 | 앱 장식과 구획의 비중이 커짐 |

## 비교 방법

- 위쪽 스타일 버튼 또는 숫자 1 / 2 / 3, 좌우 방향키로 전환합니다.
- 입력 중에는 스타일 전환 단축키가 작동하지 않습니다.
- `세 안 함께 보기`는 동일 너비의 세 안을 위아래로 배치합니다. 축소하지 않으므로 실제 글자 크기로 비교합니다.
- `이 안 크게 보기`로 단일 보기로 돌아옵니다.

## 같은 조건

세 안 모두 가상 고객 5명과 의뢰 7건을 공유합니다. 검색어·담당자·전체/구함/내놓음 필터, 정렬, 접기 상태와 상담 내용도 공유합니다. 하나의 안에서 변경한 상태가 다른 안에서도 이어지므로 같은 내용으로 스타일을 비교할 수 있습니다.

이번 구역은 의뢰/매물·거래·최소예산·최대예산·평형·매칭만 비교합니다. 실제 앱의 월세·등록일·전체 필터·원장 편집 기능을 모두 옮긴 결과는 아닙니다.

## 동작

- 고객/전화번호/상담/매물 검색, 담당자 필터, 의뢰 종류 필터
- 최소·최대 예산 열의 내림차순 → 오름차순 → 해제
- 정렬 메뉴와 열 제목의 상태 동기화, 정렬 선택의 localStorage 보존
- 고객별 및 전체 의뢰 접기/펼치기
- 고객명·상담 요약을 눌러 상담 메모 수정, 새로고침 후 보존
- 상단 상담 기록은 현재 결과의 첫 고객에 대해 열림
- 매칭 버튼은 가상 건수 안내만 표시하며 실제 후보 데이터는 연결하지 않음

주변 앱 메뉴는 정적 배치입니다. 새 고객 추가, 실제 통화, CRM/API 연결은 없습니다. 기록 저장은 `estate-ledger-directions-v1-notes`, 정렬은 `estate-ledger-directions-v1`에만 저장합니다. 앞선 시안의 저장 키와 분리됩니다.

## 확인

Ego Browser에서 세 안을 각각 캡처하고 시각적으로 비교했습니다. 검색 결과가 세 안에서 같게 나오는지, 전환 후 검색어 유지, 예산 3단계 정렬, 접기/펼치기, 상담 저장과 정렬의 새로고침 후 보존, 전체 비교와 개별 보기 복귀를 확인했습니다. 1280×800에서 페이지 가로 넘침과 헤더/본문 정렬도 확인했습니다.

입력 때 검색창을 재생성하던 부분은 수정해 활성 입력을 유지합니다. 실제 Electron 소스와 루트 DESIGN.md에는 반영하지 않았습니다. 선택한 방향이 생기면 그 방향의 타이포·밀도·형태·상태 규칙을 디자인 기준에 반영할 수 있습니다.
