# 수수료/정산 화면 개편 시안

`index.html`을 브라우저에서 직접 엽니다. 서버나 설치 없이 동작합니다. 글꼴만 CDN에서 불러오며, 인터넷이 없으면 시스템 글꼴로 표시됩니다.

이 시안의 화면은 2026년 11월 5일 실제 앱(`apps/desktop/src/renderer/routes/_authenticated/cashflow/`)에 반영했습니다. 앱과 다른 점은 아래 [앱 반영 내용](#앱-반영-내용)을 보세요.

왼쪽 메뉴 `수수료/정산` 아래 6개 화면이 실제로 이동됩니다.

| 메뉴 | 파일 | 코드 |
| --- | --- | --- |
| 캐시플로우 | `index.html` | `cashflow/index.tsx` |
| 수금 원장 (표·칸반·캘린더) | `ledger.html` | `cashflow/-ledger.tsx`, `-ledger-kanban.tsx` |
| 공동중개 수수료 | `partner-commissions.html` | `cashflow/partner-commissions.tsx` |

| 고정비 설정 | `expenses.html` | `cashflow/expenses.tsx` |

## 앱 반영 내용

서버를 고치지 않고 지금 API로 되는 범위만 넣었습니다. 그래서 시안과 다음이 다릅니다.

| 항목 | 시안 | 앱 |
| --- | --- | --- |
| 공동중개 `정산 처리` | 있음 | 없음. 처리 API가 없어 금액만 표시 |
| 공동중개 금액 이름 | 받을 돈, 줄 돈 | 파트너가 받은 우리 몫, 우리가 받은 파트너 몫. 정산 기록을 못 남겨 금액이 줄지 않으므로 사실대로 씀 |
| 직원 `정산 처리`, 선택 체크 | 있음 | 없음. 처리 API가 없어 조회와 내보내기만 |
| `확정 안 된 청구` 묶음 | 있음 | 없음. 원장 API가 작성중 청구를 내려 주지 않음 |
| `독촉함` 표시 | 있음 | 없음. 이미 만든 독촉 업무를 알 수 없음 |
| 대표·중개사 보기 전환 | 왼쪽 아래 메뉴 | 없음. 로그인한 사람의 역할을 따름 |
| 청구별 `분배 수정` 다이얼로그, 슬라이더의 파트너 선택과 `바꾸기` 확인 | 없음. 슬라이더의 `적용`으로 바로 반영 | 있음 |
| 면제·대손 전에 받은 돈의 월 수금·순이익 | 포함 | 빠짐. 서버 값을 쓰기 때문이며 아래 `발견한 문제` 7번 참고 |

데이터는 이렇게 읽습니다.

- 월 수금과 순이익: `summary.monthlyTrend`. `summary.collected`는 진행 거래 전체 누계라 쓰지 않습니다.
- 받을 돈, 오늘 처리할 것, 앞으로 들어올 돈: `ledger(all)`에서 계산합니다. 부분수금 잔액과 지난달 연체가 함께 잡힙니다.
- 공동중개, 직원 정산, 내 수수료: `GET /deals`. 직원마다 조회하던 N+1과 직원 상세의 20건 제한이 사라집니다.
- 수금 처리: 이번에 받은 금액을 입력받고 누적액을 보냅니다. 서버의 덮어쓰기 문제를 이 경로에서는 피합니다. 남은 금액을 넘거나 만원 단위 정수가 아니면 기록하지 않습니다.
- 분배 금액: 저장된 `shareAmount`를 믿지 않고 지금 청구액과 비율로 계산합니다. 규칙은 서버와 같이 행마다 내림하고 나머지를 우리 몫으로 둡니다. 이미 정산한 행만 실제 금액을 유지합니다. 받은 돈 없이 면제·취소된 청구는 합계에서 빼고, 일부 받은 뒤 면제·대손한 청구는 받은 돈까지 청구로 남깁니다.
- 받을 몫·줄 몫: 들어온 돈 기준입니다. 할인으로 청구액이 받은 돈보다 작아지면 청구액까지만 나눕니다. 면제·대손 전에 받은 돈의 파트너 몫도 포함합니다.
- 남은 돈이 없는 부분수금: 할인 승인 뒤 서버 상태가 `partial`로 남아도 화면에서는 수금완료로 다룹니다. 서버 일괄 분배 API는 이런 청구까지 바꾸므로, 있으면 건별 API로 나머지 청구만 바꿉니다.
- 거래 전체 분배 변경: 대상은 화면 목록이 아니라 그 거래의 전체 청구를 서버에서 읽어 정합니다. 슬라이더는 청구에 저장된 파트너를 유지하고, 파트너가 둘 이상인 청구는 잠급니다.
- 거래 상세: 기간 필터와 상관없이 그 거래의 청구를 전부 보여 줍니다.
- 주소를 직접 열어도 대표·매니저 전용 화면은 권한 없음으로 나옵니다. 서버 API의 역할 검사는 아직 없습니다.

## 왜 앱과 안 맞아 보였나

매물관리와 고객 원장은 평면 표인데, 수수료/정산만 카드 대시보드로 만들어져 있었습니다.

| 항목 | 지금 수수료/정산 | 앱의 다른 화면과 이 시안 |
| --- | --- | --- |
| 뼈대 | 여백 안에 둥근 카드를 쌓음 (`rounded-xl`, `rounded-2xl`) | 여백 없이 시작하고 경계선으로 나눔 |
| 머리 | 페이지마다 제목과 설명 문장 | 제목은 탭에 있으므로 툴바부터 시작 |
| 요약 | 아이콘 카드 4개를 페이지마다 복사 | 경계선으로 나눈 요약 줄 하나 |
| 툴바 | 네모난 선택 상자 | 알약 탭, 검색, 값이 없으면 이름만 보이는 필터 칩 |
| 색 | 초록 글자, 그라데이션, `emerald`·`red`·`sky` 직접 지정 | 흰 종이와 잉크색. 색은 상태와 연체에만 |
| 글자 | `text-5xl` 금액, `text-[10px]` 보조 글자 | 금액 20px, 표 13px, 가장 작은 글자 11.5px |
| 표 | 한 칸에 배지·금액·진행 막대·설명을 쌓음 | 청구·수금·잔여를 각각의 열로 분리, 36px 머리글, 38px 행 |
| 말투 | "안녕하세요, 오늘 하루도 시작합니다", "커피 한 잔 ☕" | 업무 문구만 |

토큰과 치수는 `app.css`, `property-toolbar.tsx`, `property-listings-table.tsx`, `lib/status-config.ts`의 값을 그대로 옮겼습니다. 금액 열만 매물관리와 달리 오른쪽 정렬입니다. 합계를 맞춰 보는 화면이라 자릿수가 맞아야 읽기 쉽습니다.

## 화면별 변경

**캐시플로우**
- 맨 위 줄을 `수금 − 고정비 = 순이익` 식으로 바꿔, 순이익이 어떻게 나온 숫자인지 보이게 했습니다.
- `오늘 처리할 것`을 연체, 조정 승인, 7일 내 예정, 확정 안 된 청구, 세금계산서 미기록으로 묶었습니다. 고른 달과 상관없이 항상 지금 기준입니다.
- 월별 차트에 앞으로 들어올 돈과 월 고정비 선을 넣었습니다. 막대를 누르면 그 달로 이동하고, `표`로 숫자를 볼 수 있습니다.
- 자동으로 계산하던 월 목표(`고정비 × 4`)는 뺐습니다. 사무소가 정한 목표가 아닌데 달성률처럼 보이기 때문입니다.

**수금 원장**
- 3개 버튼이 줄지어 있던 행을 `수금 처리` 하나와 `⋮` 메뉴로 줄였습니다.
- 4칸 진행 표시와 전용 색을 앱 공통 거래 단계 배지로 바꿨습니다.
- 표 위 띠에 합계를 보여 주고, 체크하면 같은 자리가 일괄 작업으로 바뀝니다. `연체`, `부분수금`을 누르면 바로 걸러집니다.
- 필터를 걸면 해당 청구 행만 남습니다.
- 칸반은 업무 보드와 같은 모양으로, 캘린더는 평면 격자로 맞췄습니다.
- 행을 누르면 매물관리 인스펙터와 같은 전환으로 거래 상세가 열립니다.

**공동중개 수수료**
- 집계만 있던 표에 `받을 돈`, `줄 돈`을 넣었습니다. 우리가 받았으면 파트너 몫을 주고, 파트너가 받았으면 우리 몫을 받습니다.
- 파트너를 펼치면 거래가 보이고, `정산 처리`로 건별 지급·입금을 기록합니다.
- 잔액은 들어온 돈 기준입니다. 부분수금분을 먼저 정산해도 나머지가 들어오면 차액이 다시 잡힙니다. 정산이 시작된 청구는 분배 비율을 바꿀 수 없습니다.

**직원 정산**
- 고객 수금이 끝난 건을 `정산 가능`으로 나눠, 지금 줄 수 있는 돈이 먼저 보입니다.
- 직원을 펼쳐 거래를 고르고 `정산 처리`합니다. `정산 가능 N건 모두 선택`으로 월말 정산을 한 번에 할 수 있습니다.
- 수금 전인 건이 섞이면 다이얼로그에서 알려 줍니다.
- 정산과 무관한 `진행 업무` 열은 뺐습니다.

**내 수수료**
- 표를 `정산 받을 수 있음`, `고객 수금 대기`, `정산 완료`로 묶어 "내 돈이 어디까지 왔나"에 답합니다.
- 고객 수금률을 함께 보여 주고, 거래 상세는 읽기 전용입니다. 다른 직원의 배분은 보이지 않습니다.

**고정비 설정**
- 카드 목록을 표로 바꾸고 맨 아래에 합계를 뒀습니다.
- 사용 스위치를 행에 바로 두고, 오른쪽에 분류별 금액과 이번 달 결제 일정을 넣었습니다.
- 앱 최소 창(폭 1279px 이하)에서는 오른쪽 요약을 접습니다.

## 서버 변경이 필요한 것

| 기능 | 지금 | 필요한 것 |
| --- | --- | --- |
| 직원 정산 처리 | 정산 상태를 바꾸는 API가 없음 | `DealParticipant` 정산 처리 API |
| 공동중개 정산 처리 | 분배를 정산 완료로 바꾸는 API가 없음. 분배마다 상태 하나뿐이라 부분수금분만 정산한 금액을 남길 수 없음 | `CommissionDistribution` 정산 처리 API, 정산한 금액 필드 (시안의 `settledAmount`) |
| 직원별 거래 펼치기, 측별 `정산 가능` | 직원 수만큼 조회해야 하고, 거래별 수금 합계만 내려옴 | 직원 정산 집계 API (참여 건별 수금 상태 포함) |
| 작성중 청구 묶음 | 작성중 청구만 있는 거래는 원장 API에 나오지 않음 (`ledger.service.ts:171`) | 작성중 포함 옵션 |
| `독촉함` 표시 | 독촉 업무가 이미 있는지 알 수 없음 | 거래별 독촉 업무 조회, 또는 시안에서 이 표시를 뺌 |

서버 변경 없이 되는 것: 캐시플로우 전체, 원장 표·칸반·캘린더, 받을 돈·줄 돈 계산(`ledger` 응답의 분배와 `collectedByOffice`, 정산 기능을 넣기 전까지), 고정비 전체.

## 코드를 보다가 발견한 문제

서버 쪽 원인은 아직 고치지 않았습니다. 2, 3, 5번은 앱 화면에서 피했고, 1, 4, 6번은 서버 변경이 필요합니다. 7번은 원장과 상세에서는 피했지만 캐시플로우의 월 수금과 순이익은 서버 변경이 필요합니다.

1. **순이익이 부풀려집니다.** 월별 수금에 파트너 몫까지 더하고, 직원 배분을 빼지 않습니다 (`cashflow.service.ts:314`, `:326`). 공동중개가 많은 달일수록 실제보다 크게 보입니다. 앱 화면에는 `직원·파트너 배분 전`이라고 표시했습니다.
2. **부분수금을 이어 받으면 앞선 금액이 사라집니다.** `collect`가 받은 금액을 더하지 않고 덮어씁니다 (`commission-payment.service.ts:98`). 500만을 받고 남은 290만을 입력하면 수금액이 290만이 됩니다. 시안은 남은 금액을 받아 누적하므로, 구현할 때 누적액을 보내거나 서버를 고쳐야 합니다.
3. **지난달 연체가 `오늘 처리할 것`에서 빠집니다.** 고른 달 범위(`preset: 'month'`)로만 조회합니다 (`cashflow/index.tsx:94`). 10월 연체는 11월 화면에 나오지 않습니다.
4. **중개사도 사무소 전체 재무를 볼 수 있습니다.** 메뉴만 숨겼을 뿐 `finance/cashflow`, `finance/ledger`에 역할 검사가 없고, 화면에도 없습니다. 주소를 직접 열거나 API를 호출하면 전 직원 수수료가 보입니다.
5. **할인을 승인해도 분배 금액과 수금 상태가 그대로입니다.** 청구액만 줄입니다 (`commission-adjustment.service.ts:131`). 앱 화면은 지금 청구액으로 다시 계산해 보여 주지만, DB의 `shareAmount`는 할인 전 금액으로 남고 정산 API를 만들 때 이 값을 쓰면 틀립니다. 승인할 때 남은 금액도 확인하지 않아, 요청 뒤 돈이 들어온 할인을 승인하면 청구액이 받은 돈보다 작아집니다. 앱은 승인을 누르는 순간 청구를 다시 읽어 확인하고 조정 ID로 청구를 찾지만, 확인과 승인 사이에 다른 사람이 수금하거나 API를 직접 호출하면 막지 못합니다. 서버 승인 API가 같은 확인을 해야 합니다.
6. **입금일을 청구마다 하나만 저장합니다.** 10월에 500만, 11월에 290만을 받으면 790만이 모두 11월 수금으로 집계되고 10월 수금은 줄어듭니다. 화면에서 고칠 수 없어 달이 바뀌는 수금에는 안내를 띄웁니다. 입금 건별 기록이 있어야 해결됩니다.
7. **일부 받은 뒤 면제·대손하면 받은 돈이 서버 집계에서 빠집니다.** `ledger.service.ts:287`, `cashflow.service.ts:164`는 `waived` 청구를 통째로 건너뛰고, 월별 수금도 `collected`, `partial`만 더합니다 (`cashflow.service.ts:314`). 앱의 원장, 상세, 캘린더, 공동중개 화면은 받은 돈을 살려 계산하지만, 캐시플로우의 월 수금과 순이익은 서버 값이라 이 돈이 빠집니다.
8. **`수금대기`, `부분수금` 배지의 글자 대비가 낮습니다.** 각각 2.4:1, 2.6:1입니다(권장 4.5:1). 공통 `StatusBadge`라서 시안은 그대로 두었습니다. `warning-strong` 같은 진한 글자 토큰으로 바꾸면 해결됩니다.

## 해볼 것

- 수금 원장에서 `수금 처리`로 금액을 일부만 입력한 뒤 캐시플로우로 돌아가 숫자가 바뀌는지 봅니다.
- 고정비에서 스위치를 끄면 캐시플로우 순이익이 바뀝니다.
- 직원 정산에서 `정산 가능 N건 모두 선택` → `정산 처리` 후 왼쪽 아래 사람 이름을 눌러 `박서연`으로 바꾸고 내 수수료를 봅니다.
- `박서연`으로 바꾸면 메뉴에 내 수수료만 남고, 다른 화면 주소는 권한 없음으로 나옵니다.
- 공동중개 거래 상세에서 분배 슬라이더를 움직이면 청구별 미리보기가 나오고, `적용`하면 같은 금액으로 저장됩니다.
- 공동중개 청구를 일부만 수금한 뒤 `조정 요청` → `대손 처리`를 승인합니다. 받은 돈과 파트너 몫이 원장, 캘린더, 공동중개 수수료에 그대로 남습니다.
- 수금 처리에 남은 금액보다 큰 값이나 소수를 넣거나, 이어 받는 입금일을 다음 달로 바꿔 봅니다.
- `컬럼`으로 원장 열을 끄고, 표 머리글의 `청구`, `예정일`로 정렬합니다.

## 시안과 앱의 차이

- 거래 17건, 청구 34건, 직원 6명, 파트너 4곳, 고정비 11건은 모두 가상 데이터입니다. 기준일은 2026년 11월 4일(수)로 고정했습니다. 6~8월 수금액은 고정값이고, 9월부터는 청구 내역에서 계산합니다.
- 변경 내용은 `estait-cashflow-demo-v3` 키로 이 브라우저에만 저장합니다. 화면 오른쪽 아래 `시안 데이터 초기화`로 되돌립니다. 이전 `v1`, `v2` 저장 내용은 지금 계산 규칙으로 되살릴 수 없어 처음 열 때 지우고 안내를 띄웁니다. 사이드바 접힘과 원장 열 설정은 그대로 옮깁니다.
- 수수료/정산 밖의 메뉴와 `거래관리에서 보기`는 안내 문구만 표시합니다.
- 선택 상자와 날짜 입력은 브라우저 기본 부품입니다. 앱에서는 지금의 shadcn 부품이 들어갑니다.
- 탭 드래그, 표의 열 폭 조절과 방향키 이동은 넣지 않았습니다. 빈 화면과 권한 없음 화면은 있지만 로딩 스켈레톤은 없습니다.
- 차트의 수금·예정 색(`#0f7b6c`, `#79b8ac`)은 색 대비 검증을 통과한 값입니다.
- 앱 기본 창(1440×900)과 최소 창(1200×760)에서 확인했습니다. 최소 창의 원장은 가로 스크롤이 생기며, 왼쪽 거래 열과 오른쪽 작업 열은 고정됩니다.
