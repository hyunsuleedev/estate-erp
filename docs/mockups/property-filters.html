이 예시의 설계 의도

· 2단 구조 유지 — 1행: 거래유형 탭 + 단지/동/호 + 통합검색. 2행: 필터 칩 바. (기존 index.tsx 구조 그대로)
· 1차 칩(항상 노출): 지역 · 유형 · 상태 · 가격 · 면적 + 신규 ●확인경과 · ●층수. 파란 점이 신규 추가분.
· 「상세필터」 묶음: 매물확인상태 · 입주/세입자 · 광고채널 · 가격변동 · 등록일 · 숨김매물 — 그룹화한 대형 팝오버. 칩 우측 3 배지로 적용 개수 표시.
· 회색 "추후" 그룹: 담당 중개사 · 소유주검증 · 융자 — 스키마에 전용 필드가 없어 비활성 처리. 자리만 잡아둠.
· 담당자 위치 참고: 질문에서 고른 미리보기엔 [담당자▾]가 1차 칩에 있었지만, 2번 질문(신규 필드 → 추후)에 맞춰 「추후」 그룹으로 내렸습니다. 담당자 필드(assignedToId)가 매물 모델에 추가되면 1차 칩으로 승격하는 것을 권장.

킬러 필터: 확인경과 (매물 생존 확인)

중개사는 등록된 매물이 아직 살아있는지 — 소유주가 다른 데서 거래했거나 매물을 거둬들이지 않았는지 — 주기적으로 소유주에게 확인 전화를 돌립니다. "마지막 확인 이후 N일 지난 매물"을 골라 일괄로 전화 확인하는 게 매물장 관리의 핵심 루틴인데, 지금은 이걸 골라낼 필터가 없습니다. 스키마의 confirmedAt/nextConfirmAt이 이미 있어 스키마 변경 없이 필터만 추가하면 됨(단, 백엔드 where 빌드 + 정렬 케이스는 신규 작성 필요).

구현 난이도 (정확히 두 갈래)

① 스키마 마이그레이션 불필요 + 백엔드가 이미 지원 (프론트만): 매물확인상태(checkStatus) · 공동중개 · 입주가능일 범위 · 광고 유무. 이건 칩만 노출하면 됨.
② 스키마 마이그레이션 불필요하지만 백엔드 쿼리 변경 필요 (where/정렬 신규): 확인경과(confirmedAt·nextConfirmAt — 컨트롤러는 nextConfirmFrom/To만 받음, 경과일 계산 로직 추가) · 층수(Unit.floor) · 즉시입주(moveInAvailableType) · 세입자상태(Tenant.status) · 광고채널(channel 별) · 가격변동(PriceHistory 조인) · 등록일(createdAt) · 숨김(isHidden). 그리고 유형·상태를 단일선택→다중선택 체크박스로 바꾼 부분도 여기 해당 — 현재 API는 siteType/status를 단일 값 equals로만 받으므로, 다중선택은 DTO를 배열로 받고 where를 IN으로 바꾸는 백엔드 작업이 필요함.
③ 스키마 신규 필드 필요 (회색 "추후"): 담당 중개사(assignedToId) · 소유주 검증 · 융자/근저당 비율 · 관리비. 매물 모델에 컬럼 없음.

⚠ 정렬 주의

현재 백엔드 resolveOrderBy는 receivedAt/createdAt/updatedAt만 지원합니다. 드롭다운의 「가격 낮은순/높은순」과 「확인 오래된순/최근순」은 지금은 동작하지 않고 receivedAt으로 폴백됩니다 — resolveOrderBy에 price/confirm 케이스를 추가해야 실제 정렬이 됩니다. 또 기존 "확인일" 정렬은 실제 확인 시각(confirmedAt)이 아니라 updatedAt 기반이라, 인라인 편집만 해도 갱신되는 점을 보정 권장.

거래유형 탭 연동

매매·전세 탭 → 「가격」 칩이 가격 범위만, 월세 탭 → 보증금+월세 노출. (탭 따라 가격 칩 라벨/내용 전환)
