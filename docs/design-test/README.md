# 디자인 백지 테스트 키트

여러 AI 모델/에이전트에게 **디자인 가이드 없이** Estate ERP 화면을 그리게 하고, 같은 기준으로 비교하기 위한 세트.

## 무엇을 측정하나

가이드를 **안 주는** 테스트는 모델의 *raw 디자인 능력 + 도메인 추론력*을 본다.
가이드를 **주는** 테스트(`../Estate-ERP-디자인-설계-지시서.pdf`)는 *지시 준수력 + 일관성*을 본다.
이 키트는 전자(백지)를 위한 것이며, 둘을 A/B로 비교하면 가장 값지다.

## 핵심 설계 원칙

> **백지 ≠ 맥락 없음.** 무슨 제품인지조차 모르면 디자인이 아니라 추측을 측정하게 된다.
> 그래서 **맥락·도메인 사실은 주고, 디자인 결정만 뺀다.** 그 경계가 테스트의 공정성을 만든다.

## 파일

| 파일 | 역할 |
|---|---|
| `00_CONTEXT_BRIEF.md` | 모든 프롬프트에 붙이는 공통 프로젝트 설명 (제품·사용자·데이터·표기규칙·샘플데이터) |
| `01_TASK_PROMPTS.md` | 화면별 과제 프롬프트 5개(+선택 1). *무엇을* 그릴지 통제, *어떻게*는 개방 |
| `02_EVALUATION_RUBRIC.md` | 6축 30점 채점표. 블라인드·다회차 권장 |

## 실행 순서

1. **프롬프트 조립**: `[00_CONTEXT_BRIEF 전체] + [01의 과제 1개]` = 한 입력.
2. **동일 입력 고정**: 모든 모델·모든 회차에 토씨 안 바꾸고 같은 텍스트를 던진다.
3. **회차 반복**: 백지는 출력이 매번 다르다 → 과제당 **3회 이상** 돌린다.
4. **블라인드 채점**: 결과물 HTML을 브라우저로 열고, 어느 모델인지 모르는 상태로 `02` 루브릭으로 채점.
5. **집계**: 축별·분산까지 본다. 총점만 보지 않는다.

## A/B 비교 (선택, 강력 추천)

같은 모델로:
- (A) 이 키트 = 가이드 없음
- (B) `../Estate-ERP-디자인-설계-지시서.pdf` 첨부 = 가이드 있음

→ 가이드가 결과를 **개선했는지 가뒀는지**가 드러난다. 특히 루브릭 축6(통찰)이 가이드 때문에 떨어지면, 가이드가 너무 빡빡하다는 신호다.

## 주의

- 과제 프롬프트에 색·레이아웃·컴포넌트 힌트를 **절대 추가하지 말 것.** 추가하는 순간 백지 테스트가 아니게 된다.
- 단, 출력 형식(단일 HTML·1440px·샘플데이터 채우기)은 통일해야 비교가 된다. 이건 `01`의 "공통 출력 지시"에 이미 박혀 있다.
