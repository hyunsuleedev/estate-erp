# 평가 루브릭 (모델 비교 채점표)

> **왜 필요한가**: "그냥 보고 예쁜 거 고르기"는 주관적이고 재현 불가하다. 같은 기준으로 점수를 매겨야
> 모델 A vs B를 사과 대 사과로 비교할 수 있다. 각 과제 결과물을 아래 6개 축으로 채점하라.
> 채점자는 결과물이 **어느 모델 것인지 모르는 상태(블라인드)**로 보는 게 가장 좋다.

---

## 채점 방법

- 각 축 0~5점. 6축 × 5점 = **과제당 30점 만점**.
- 과제 5개(+선택 1개) 합산해 모델별 총점 비교.
- **회차마다 다르다** → 같은 과제를 같은 모델로 **최소 3회** 돌려 평균/분산을 본다. (백지 테스트는 출력이 매번 달라서 1회로 판단하면 위험)
- 점수만 보지 말고 **"왜 이 점수인지" 한 줄 근거**를 같이 적어라. 나중에 패턴이 보인다.

---

## 6개 평가 축

### 축 1. 도메인 정확성 (Domain correctness) — 0~5
> 한국 부동산 중개 업무를 제대로 이해했는가.

| 점수 | 기준 |
|---|---|
| 5 | 표기 규칙(금액 `15억 8,000`·면적 m²+평·주소 축약) 완벽. 상태 단계명 정확. 매도/매수 수수료 분리 등 도메인 개념을 정확히 반영 |
| 3 | 큰 틀은 맞으나 일부 표기 어색(예: 금액을 "1,580,000,000원"으로) 또는 단계 일부 누락 |
| 1 | 부동산 화면처럼 보이지만 한국 맥락이 거의 없음 (달러 표기, 영어 라벨 등) |
| 0 | 과제와 무관하거나 도메인을 오해 |

### 축 2. 과제 완수도 (Task completeness) — 0~5
> 과제가 "반드시 포함할 것"으로 요구한 요소를 다 넣었는가.

| 점수 | 기준 |
|---|---|
| 5 | 필수 요소 전부 + 기본 상태 + 빈 상태까지 |
| 3 | 필수 요소 대부분, 1~2개 누락 또는 빈 상태 없음 |
| 1 | 절반 이하만 구현 |
| 0 | 요구한 화면이 아님 |

### 축 3. 정보 위계 & 밀도 (Hierarchy & density) — 0~5
> 40~60대 사용자가 많은 정보를 "정돈된 상태로" 빠르게 읽을 수 있는가.

| 점수 | 기준 |
|---|---|
| 5 | 정보 밀도가 높으면서도 위계가 명확. 중요한 것(금액·상태)이 먼저 읽힘. 스캔하기 쉬움 |
| 3 | 읽을 만하나 밀도가 너무 낮거나(휑함) 너무 높아(빽빽) 한쪽으로 치우침 |
| 1 | 위계 불분명, 뭘 먼저 봐야 할지 모름 |
| 0 | 정보가 뒤죽박죽 |

### 축 4. 시각적 완성도 (Visual craft) — 0~5
> 색·타이포·간격·정렬의 기본기. "모던 SaaS"로서 신뢰감.

| 점수 | 기준 |
|---|---|
| 5 | 일관된 색·타이포 시스템, 정렬 정확, 여백 리듬 좋음. Linear/Notion급 완성도 |
| 3 | 무난하나 색 충돌·정렬 어긋남·폰트 과다 등 거슬리는 점 1~2개 |
| 1 | 아마추어 티(원색 남발, 정렬 깨짐, 기본 브라우저 스타일) |
| 0 | 디자인이라 부르기 어려움 |

### 축 5. 일관성 & 재사용 (Consistency) — 0~5
> 같은 종류 요소(매물 카드·상태 뱃지·버튼)를 화면 내내 일관되게 다뤘는가. 여러 과제를 같은 모델로 돌렸을 때 시스템이 유지되는가.

| 점수 | 기준 |
|---|---|
| 5 | 한 화면 내 동일 요소가 완전 일관. 과제 간에도 같은 디자인 언어 유지 |
| 3 | 대체로 일관하나 같은 뱃지/카드가 자리마다 미묘하게 다름 |
| 1 | 요소마다 제각각 |
| 0 | 일관성 개념 없음 |

### 축 6. 통찰 & 제안력 (Insight) — 0~5
> 시키지 않았는데 업무를 이해해서 더한 것. 백지 테스트에서 가장 변별력 있는 축.

| 점수 | 기준 |
|---|---|
| 5 | 과제에 없던 유용한 요소를 도메인 이해 기반으로 제안 (예: 연체 수금 강조, D-day 뱃지, 단계 경과 경고, 빈 상태 카피). "오 이건 생각 못 했네" |
| 3 | 기본은 충실하나 시킨 것 이상은 없음 |
| 1 | 과제를 좁게만 해석, 빠진 맥락 많음 |
| 0 | 엉뚱한 것을 더함 |

## 채점표 템플릿 (복사해서 사용)

```
모델: ___________   과제: ___________   회차: __ / 3   채점자: _____

축1 도메인정확성  [ ]/5  근거:
축2 과제완수도    [ ]/5  근거:
축3 위계·밀도     [ ]/5  근거:
축4 시각완성도    [ ]/5  근거:
축5 일관성        [ ]/5  근거:
축6 통찰·제안     [ ]/5  근거:
───────────────────────
합계 [ ]/30

한 줄 총평:
가장 인상적이었던 점:
가장 큰 약점:
```

## 모델 비교 집계표 (예시)

| 모델 | 과제1 | 과제2 | 과제3 | 과제4 | 과제5 | 합계 | 분산(안정성) |
|---|---|---|---|---|---|---|---|
| 모델 A | /30 | /30 | /30 | /30 | /30 | /150 | 높음=불안정 |
| 모델 B | /30 | /30 | /30 | /30 | /30 | /150 | |
| 모델 C | … | | | | | | |

> **해석 팁**:
> - **총점**만 보지 말 것. 축별로 보면 "A는 도메인 정확성↑ 시각↓, B는 반대" 같은 성격 차이가 드러난다.
> - **분산**이 큰 모델은 "잘 나올 때도 있지만 들쭉날쭉" → 프로덕션 도구로는 위험.
> - 축6(통찰)에서 점수 차가 크게 벌어지면 그게 모델 간 "진짜 실력" 차이일 가능성이 높다. 나머지 축은 가이드로 메울 수 있지만 통찰은 어렵다.

## 다음 단계: 가이드 유무 A/B (선택)

같은 모델로 **가이드 없이(이 백지 테스트)** 한 번, **가이드 주고**(`Estate-ERP-디자인-설계-지시서.pdf`) 한 번 돌려서 비교하면:

- 가이드가 점수를 **올렸으면** → 가이드가 제 역할을 함.
- 가이드가 축4·5(완성도·일관성)는 올렸는데 축6(통찰)을 **내렸으면** → 가이드가 모델을 과하게 가둔 것. 가이드를 느슨하게 조정할 신호.
