# 부동산이지 비교 조사 및 Estate ERP 고도화 반영 보고서

- 조사일: 2026-07-16
- 조사 대상: `https://bdseasy.com` 데모 계정
- 비교 대상: Estate ERP 웹 (`apps/web`)
- 원칙: 데모 계정 내부 CRUD만 수행하고, 결제·문자/DM 발송·광고 송출·공적장부 발급처럼 비용이나 외부 전송이 발생할 수 있는 기능은 실행하지 않았다.

## 1. 결론

부동산이지의 가장 큰 장점은 기능 수 자체보다 **중개 업무의 연결 관계를 화면에 드러내는 방식**이다. 고객 상세에서 일정, 상담일지, 의뢰, 연관 부동산, 계약을 한 번에 보고 추가할 수 있고, 캘린더에는 계약금·중도금·잔금뿐 아니라 실거래 및 임대차 신고기한과 임대차 만기까지 같이 표시된다. 부동산 원장은 단지·동·호 단위 정보와 거래·상담·사진·공적장부 진입점을 한 화면에 모은다.

Estate ERP는 데이터 구조와 거래→계약→정산 파이프라인이 더 체계적이고, 현재 UI도 부동산이지보다 차분하고 현대적이다. 다만 실무 속도 측면에서는 연락처·매물·상담·업무를 오가는 동작 수와 메뉴 탐색 부담을 더 줄여야 한다. 이번 1차 고도화는 그 차이를 줄이는 데 집중했다.

## 2. 전체 메뉴와 기능 구조

### 부동산 원장

- 원장 관리: 즐겨찾기 단지, 주소·동·호, 거래 건수, 상담·사진 연결
- 지도: 지적도·로드뷰·재개발/재건축 등 지도 레이어, 매물 그룹 저장
- 만기 관리: 3/6/12개월 기준, 입주 상태 변경, 일괄 삭제
- 임대사업자: 임대사업자 정보 검색
- 공적장부: 소재지 추가·불러오기·발급 신청·일괄 출력/조회
- 등기 변동 알림: 소재지 저장과 등기 변동 알림 신청

### 매물

- 매물 접수: 부동산 유형, 거래 유형, 유입 경로, 고객·주소·가격·설명 입력
- 매물 관리: 다중 필터, 상태·광고 정보, 상담·사진·고객 연결, 일괄 작업
- 부동산렛츠 광고: 광고 추가·상태·삭제
- 포털 광고(BETA): 포털 공유·추가·상태·삭제
- KB 모니터링 및 네이버 모니터링: 광고 순위·중복·설명 복사/인쇄·AI 설명 요청

광고 검증과 송출은 CP/API 계약 및 외부 계정 권한이 필요한 영역이므로 Estate ERP의 즉시 구현 범위에서는 제외하는 것이 맞다.

### 고객

- 고객 관리: 유형, 구분, 등급, 담당자, 연락처, 주소, 메모, 타부동산/블랙 여부
- 의뢰 접수: 기존 고객 또는 신규 고객, 거래 유형, 금액, 입주 조건, 상세 요구사항
- 의뢰 관리: 유형·거래·금액·중요도·담당자·메모 필터
- 고객 상세: 일정, 상담일지, 의뢰, 연관 부동산, 계약을 한 화면에서 조회·추가

### 마케팅/커뮤니케이션

- 일정 관리: 계약·만기·상담/임장·세무·기타 일정 및 공휴일 필터
- 상담 일지: 기간, 고객, 상담 유형, 상담 내용 검색 및 추가
- 통화 내역: 모바일 앱 연동, 고객·번호·상담 내용 연결 및 수정
- DM 관리(BETA): DM 그룹, 주소/건축물 기반 대상 관리
- DM 템플릿: 인쇄/PDF용 편집 템플릿
- 소유자 주소록: 주소·동·호 기반 소유자 검색

### 계약과 서류

- 계약 관리 및 가계약 관리
- 계약 생성: 거래 유형, 부동산 소재지, 금액, 당사자, 일부 임대차 정보
- 필요 서류: 공제증서와 약관, 인쇄
- 공적장부: 계약과 연결된 장부 발급·출력·조회

### 운영

- AI 히스토리
- 사무실 게시판
- 결제/구독 관리
- 매출 관리: 계약 연결, 실수령 보수, 수금일, 입금계좌, 메모
- 배분 비율 관리
- 사용자/비밀번호/휴대폰 설정
- 공지사항, FAQ, 문의 게시판

## 3. 실제 CRUD 검증

### 고객

1. `Codex 테스트 고객`을 개인고객·기타 유형으로 생성했다.
2. 고객 상세에서 일정·상담·의뢰·연관 부동산·계약 섹션이 함께 표시되는 것을 확인했다.
3. 이름을 `Codex 테스트 고객 수정됨`으로, 메모를 수정했다.
4. 목록 검색으로 다시 찾은 후 선택 삭제했다.
5. 필터 입력값에만 이름이 남고 결과 행은 사라진 것을 재확인했다.

### 일정

1. 2026-07-30에 `Codex 테스트 일정`을 기타 일정으로 생성했다.
2. 월간 캘린더에 일정이 즉시 나타나는 것을 확인했다.
3. 제목과 내용을 수정했다.
4. 일정 상세에서 삭제하고 캘린더에서 사라진 것을 재확인했다.

두 테스트 모두 생성→조회→수정→삭제 왕복을 완료했으며 테스트 데이터는 남기지 않았다.

## 4. 부동산이지에서 배울 부분

1. **고객 중심 작업 허브**: 고객 상세에서 상담, 일정, 의뢰, 매물, 계약을 바로 연결한다.
2. **법정·계약 일정 자동 가시화**: 신고기한과 만기를 일반 일정과 같은 캘린더에 표시한다.
3. **동·호 단위 원장**: 단지→동→호실을 탐색하면서 거래·상담·사진을 즉시 확인한다.
4. **명시적 매출·배분 업무**: 계약 이후 수금과 직원별 배분을 별도 실무 화면으로 제공한다.
5. **접수 동선 분리**: 매도/임대는 매물 접수, 매수/임차는 의뢰 접수로 안내한다.

## 5. 그대로 따라 하지 않을 부분

- 상단 1차 메뉴 아래에 많은 하위 기능이 숨어 있어 전체 위치를 익히기 어렵다.
- 긴 입력 폼과 중첩 모달이 많고, 성공 알림 뒤에 이전 모달 상태가 잠시 남는 경우가 있다.
- 아이콘명이 `search`, `note`, `add`처럼 접근성 이름에 그대로 노출되는 곳이 있다.
- 일부 화면에서 `NaN건 추가` 같은 상태 표시 오류가 보였다.
- 조회·수정·삭제·외부 발급이 비슷한 시각적 무게로 배치되어 위험 작업 구분이 약하다.
- 공적장부, 광고, DM, 결제처럼 외부 비용·전송이 있는 동작의 사전 영향 안내가 충분하지 않다.

Estate ERP는 Linear/Notion 스타일의 낮은 시각적 소음, 명확한 포커스 상태, 키보드 조작, 위험 작업의 확인 단계를 유지해야 한다.

## 6. 이번에 Estate ERP 웹에 반영한 1차 개선

- 인증 후 리다이렉트에서 발생하던 `Maximum update depth exceeded` 반복 렌더를 제거했다.
- 사이드바를 시작, 매물·공간, 고객·상담, 거래·계약, 업무·운영 5개 그룹으로 재구성했다.
- 전체 검색을 페이지 이동·엔티티 검색·빠른 생성이 결합된 명령 센터로 확장했다.
- `Ctrl/⌘+K`, `G→D/P/C/S/T/A` 페이지 이동 단축키를 추가했다.
- 연락처 검색창을 항상 보이게 하고, 짧은 테이블도 작업 영역 전체 폭을 사용하도록 했다.
- 연락처 퀵시트에 상담 기록, 후속 업무, 구매 희망조건, 매물 연결 액션을 추가했다.
- 매물 목록의 상세 열기를 네이티브 버튼으로 바꿔 Enter/Space와 포커스 표시를 지원했다.

## 7. 다음 구현 우선순위

### P0 — 매일 쓰는 공통 작업대

- 전역 검색 결과에서 단지·매물·고객의 정확한 상세 화면으로 바로 이동
- 연락처 퀵시트 액션을 매물·상담·구매고객·통화 화면에도 같은 패턴으로 확장
- 삭제·발송·외부 요청에 공통 확인/결과/감사 로그 패턴 적용

### P1 — 고객과 매물의 실무 허브

- 고객 상세 타임라인에 상담·전화·업무·일정·매칭·거래를 시간순으로 통합
- 매물 상세에 소유자/세입자, 가격 이력, 상담, 광고, 일정, 계약 진행을 한 화면에 배치
- 저장된 보기, 고정 열, 사용자별 필터/정렬 프리셋을 서버에 저장
- 달력에서 계약금·중도금·잔금·만기·신고기한을 명시적 이벤트로 관리

### P2 — 외부 연동 이후

- 정식 CP/API 계약이 확보된 뒤 네이버/포털 광고 상태·순위·검증 연동
- 공적장부 발급, 등기 변동 감시, DM/SMS는 비용·권한·개인정보 감사 체계를 먼저 설계

## 8. 최종 판단

부동산이지의 기능을 모두 복제하는 것이 목표가 아니다. Estate ERP가 먼저 완성해야 할 것은 **고객에서 상담·의뢰·매물·거래·계약·정산으로 이어지는 끊김 없는 실무 동선**이다. 이번 1차 개선은 그중 탐색 속도, 연락처 즉시 작업, 화면 안정성, 접근성을 실제 코드에 반영했다. 다음 배치는 고객·매물 상세를 완전한 작업 허브로 만드는 것이 가장 효과가 크다.
